# Install from local packages

Use locally supplied, verified package files. These commands do not download
packages or dependencies. Install the required system packages beforehand
from your own local media. The installer enables the service without starting
it. Supply the gateway URL, pinned TLS CA, catalog public key and agent YAML
from your administrator.

```sh
# Debian / Ubuntu (local file):
sudo dpkg -i /absolute/path/allowops-agent_0.2.0_amd64.deb
# RHEL / Rocky / Alma / CentOS (local file):
sudo rpm -Uvh /absolute/path/allowops-agent-0.2.0-1.x86_64.rpm

sudo install -o root -g root -m 0644 /absolute/path/catalog.pub.pem \
  /etc/allowops/catalog-keys/catalog.pub.pem
sudo install -o root -g root -m 0644 /absolute/path/agent.yaml /etc/allowops/agent.yaml

# agent.yaml must have the same upstream and ca_pin used by join.
# Compute the pin from the supplied TLS CA certificate, not the host identity CA.
ca_pin=$(openssl x509 -in /absolute/path/gateway-tls-ca.crt -outform DER \
  | openssl dgst -sha256 -r | cut -d ' ' -f 1)
sudo allowops-agent join --upstream https://gateway.example.com:443 \
  --token-file /absolute/path/join-token.txt --ca-pin "sha256:$ca_pin"
sudo systemctl start allowops-agent
sudo -u allowops allowops-agent status
```

Join tokens are generated by the gateway, not chosen by the installing host.
Use a 0600 file with `--token-file`, or pipe the token to `--token-stdin`.
Exactly one of `--token`, `--token-file` and `--token-stdin` is required.
Each source accepts at most 4 KiB, trims surrounding whitespace and rejects
an empty token. The legacy `--token` remains available for compatibility. Package signatures and
checksums are verified according to your release process before installation.
